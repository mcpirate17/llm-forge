# Native commit recovery

`make governance-commit COMMIT_ARGS='-m message ...'` invokes `forge candidate commit --repo PATH -- <git commit arguments>`. The wrapper admits the repository and limits, takes the Git-common exclusive review lease, captures recovery, runs Git with normal hooks, waits for the child and releases the lease. It reports the recovery ref on stderr before starting Git. Snapshot failure blocks the commit. A Git exit code is returned unchanged; when Git dies from a signal, the CLI releases its lease and terminates with the same signal. For noninteractive commands the wrapper starts Git in its own process group. On parent SIGINT or SIGTERM it forwards the signal to that owned group, waits one second, then kills the group and polls for Git to be reaped for up to five seconds. If that deadline expires, it reports a cleanup failure; any surviving inherited descriptor keeps the lease. Group members that deliberately create a new session or process group escape this teardown. The CLI reflects the parent signal after cleanup.

When any standard stream is a terminal, Git stays in the foreground process group so prompts and terminal job control continue to work. On parent-only SIGINT or SIGTERM the wrapper forwards to the Git PID, waits one second, then kills Git and polls for reaping for up to five seconds; hook descendants in the shared foreground group may survive. The wrapper warns of that limitation. Descriptors held by surviving descendants keep the flock until they close; the parent never explicitly unlocks the shared open-file description. To obtain isolated-group cancellation, run with all standard streams redirected and accept noninteractive Git behavior.

SIGKILL cannot be caught for cleanup. On Linux the Git child requests a parent-death SIGTERM and checks for a parent-death race before exec; that is best effort for Git only and does not guarantee termination of hooks or descendants. Their inherited descriptors can retain the lease. Interrupts received during bounded snapshot capture are handled before starting Git, but do not interrupt an individual filesystem read.

An unborn symbolic HEAD is supported: the two recovery parents are root commits. An absent default or alternate index is treated as empty only while its exact absence and containing directory identity remain stable through capture. The ref `refs/snapshots/forge/snapshot-...` identifies a merge commit: `REF^1` is the staged index, and `REF^2` is admitted worktree content. Examples: `git ls-tree -r REF^1`; `git show REF^2:path/to/file > recovered-file`. Review the content and choose a destination before restoring it. Recovery refs are retained and require deliberate maintenance.

Default and maximum limits: 100,000 visited files and directories including inspected ignored entries, 64 MiB per file, 2 GiB per recovery tree; `--max-entries`, `--max-file-bytes`, and `--max-total-bytes` allow lower limits. Non-UTF-8 or unsafe paths, unsupported symlinks, special files, submodules, nested Git metadata, unmerged or sparse/extended indexes, invalid index files and invalid HEAD state are rejected. Ignored directories without paths tracked in HEAD or the index are pruned before traversal; tracked descendants preserve access through ignored parents. Tracked and nonignored untracked files are admitted; ignored untracked files and empty directories are excluded. Actual worktree bytes and executable mode are recorded without Git content filters. Both recovery trees use the existing snapshot symlink safety checks. The root Git metadata directory is excluded.

SIGINT or SIGTERM while waiting for the exclusive lease cancels that wait before snapshot creation or Git invocation. Capture detects changes to the index, HEAD, and observed filesystem identities and metadata before publishing. It uses the repository's trusted-parent assumption and is not atomic against a hostile same-UID writer or uncooperative process changing files after the final check. Governance leases serialize cooperating participants; coordinate other writers separately. Incomplete capture can leave unreachable Git objects but no recovery ref and no Git commit invocation. Existing nonmatching `GIT_DIR`, `GIT_WORK_TREE`, or `GIT_COMMON_DIR`, and alternate object-directory environment overrides, are refused. A bounded `GIT_INDEX_FILE` is supported.

Snapshot capture records the staged index tree and admitted worktree tree in the recovery ref; capture itself preserves the index file bytes. Once capture completes, the real Git command and its hooks may update index metadata or files. The wrapper does not restore or roll back those Git or hook side effects.

The descriptor in `LLM_GOVERNANCE_COMMIT_LOCK_FD` is inherited into Git and must remain open through the native hook. After a review verifies the incoming descriptor it marks it close-on-exec, preventing accidental inheritance into stage subprocesses. Commit deliberately re-enables inheritance only in its Git child. A token alone does not authorize inheritance. The legacy Python review lock now fails on token-only, closed or unheld inherited descriptors; Python callers that deliberately close descriptors need to migrate their hook. Configure the host hook to run native `candidate attest-message` for fresh attestation; the wrapper does not alter hooks or bypass review. Attestation requires a fresh complete passing review bound to the selected candidate tree, policy and operator grants. Existing `candidate review`, Python `governance_lock` and unrelated CLI commands remain available. The Python `candidate_review.cli commit`, `run_locked_git_commit` and `snapshot_working_tree` entry points are retired; external callers must use the native command.

The removed snapshot compatibility target's cases map to `candidate_commit_snapshot_tests` (ref identity, separate trees, unstaged and untracked bytes, ignored files, unchanged shared index, HEAD ancestry, modes, collisions and failure) and `native_candidate_commit` (actual Git/hook path, wrapper exit and inherited lease). The old private-index-file cleanup observation is inapplicable because no private index file is created. Non-repository and failed snapshot cases now fail closed. The former non-commit-argument unit case maps to the native process test verifying the child argv always begins with `git commit`. The former token-only hook case is intentionally replaced with native open-descriptor inheritance and explicit invalid-descriptor cases. Historical migration reports remain historical.
