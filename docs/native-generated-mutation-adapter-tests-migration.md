The 17 named cargo-mutants adapter cases in `src/conductor/test_mutation_engine_cargo.py` and 12 named fest adapter cases in `src/conductor/test_mutation_engine_fest.py` are covered by Rust-owned PyO3 targets `python_contracts_mutation_engine_cargo.rs` and `python_contracts_mutation_engine_fest.rs`. The original 29-case CPU-only pytest baseline passed. The Rust targets preserve the exact synthetic report rows, status refusals, receipt schema and precision, configured engine bounds, and child-environment assertions. Their fixture dictionaries, assertions, and case algorithms live in Rust; the targets call existing Python production APIs through PyO3. They do not execute cargo-mutants, fest, generated campaigns, or worktree creation.

The checked-in fixture manifests `src/conductor/testdata/cargo/generated_cargo_campaign_fixture.json` and `src/conductor/testdata/fest/generated_fest_campaign_fixture.json` are read through the production campaign loader and remain unchanged. The cargo suite additionally asserts the existence of the manifest's `native/conductor-native/src/hook_merge.rs` source path. It treats `native/conductor-native/Cargo.toml` as a manifest-path string and does not read the file. The fest manifest's `src/conductor/gate_rollout.py` and `src/conductor/test_gate_rollout.py` source/test paths and hashes are historical fixture payload data here: these cases do not read either file or consume the original test module. The synthetic survivor baselines are fixture inputs, not campaign evidence.

Independent source-to-Rust parity and consumer review passed for all 29 named cases. The two covered Python originals were retired, and no live module imports either test module. Exact Rust targets and scoped Clippy with warnings denied were run before retirement and rerun afterward. No synthetic fixture in this cohort is campaign evidence.
