# Import declaration contract migration

The 31 named cases in `src/conductor/candidate_review/test_import_declaration.py` are covered by Rust-owned PyO3 contracts in `native/conductor-native/tests/python_contracts_candidate_import_declaration_core.rs` (22 direct API, manifest, and tree-scope cases) and `python_contracts_candidate_import_declaration_integration.rs` (9 changed-source review cases). The original 31-case pytest baseline passed before migration. Both exact Rust targets passed (22 + 9) with two Cargo jobs and one test thread; scoped Clippy passed with warnings denied.

The direct target preserves PEP 503 spelling, requirement parsing, manifest ownership and dependency sets, absolute and runtime-only imports, empty or declared metadata resolution, exact nested tuple findings, and default or `src/` dependency-tree boundaries. The integration target preserves changed-file status/classes, source and manifest contents, review findings and severity, the no-file metric, the strict-tree metric, test-file exclusion, syntax-error delegation, and scoped runtime-test-tool exemptions. Rust fixtures construct the production `ReviewContext`, `Candidate`, and `Change` objects with the original field types and values. They prepare the same snapshot manifest/source/registry/probe files and patch the production metadata provider with an exact no-argument callback. The source suite's Git anchor and grandfather inventory are unrelated to the import-declaration check and are not read by it; the Rust fixture does not create that extra repository.

Independent case-by-case parity and consumer review passed, and the Python original was retired. No live code imports that test module; `_gate_context` remains available to its other tests. The exact Rust targets and scoped Clippy were rerun after retirement. The Rust tests call existing Python production APIs through PyO3 but keep test inputs and assertions in Rust. No retired pytest suite is launched from Rust.
